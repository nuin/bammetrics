# E2 Release Artifacts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One command, `scripts/release.sh`, builds three static or universal BAMmetrics 0.34.2 binaries from one commit, with `SHA256SUMS`, a CycloneDX SBOM and a Homebrew formula, and each binary passes the golden, PDF and concordance gates.

**Architecture:** Linux binaries are built with musl inside `rust:*-alpine` containers on Docker Desktop (arm64 natively, amd64 under emulation), the same route as `scripts/build-linux.sh`. The macOS universal binary is `lipo` of two rustup builds. Gates reuse the existing suites: `BAMMETRICS_BIN` points the golden suite and the concordance modules at a release binary, either directly, through a Docker shim, or through Rosetta.

**Tech Stack:** bash, Docker Desktop 29, Alpine musl, rustup (keg-only Homebrew formula), cargo-auditable, cargo-cyclonedx, lipo, Python 3 stdlib, pytest (tests/harness).

**Spec:** `docs/superpowers/specs/2026-11-25-embedding-design.md`, section 5.2, the E2 row of section 6, ED3, ED5, section 9. Owner answer EQ2 (2026-11-26): the Linux checks run in Docker Desktop on this Mac, linux/arm64 native, linux/amd64 emulated, emulated speed recorded as emulated.

**Base:** branch `e2/release` from `e1/machine-contract` at 9551cee (PR #70, not merged). Worktree `/Users/nuin/Projects/bammetrics-e2`.

## Global Constraints

- Version 0.34.2 (ED11 patch numbering).
- A1: no change in metric output bytes. Golden and concordance give the same result before and after; only version lines and PDF sizes may change in `tests/golden` and `tests/report`.
- A3: every artifact comes from one script, one input commit and one sha256.
- A5: no GitHub Actions job added, no workflow file edited.
- A6: fake data only, in fixtures, containers and docs.
- ED3: feature `pdf` (and the default `parquet`) in every release binary.
- ED5: a release is a tag `vX.Y.Z` plus `scripts/release.sh`. In this wave nothing is tagged, pushed or uploaded: `--publish` is written and tested with `--dry-run` only.
- rustc 1.92 or later in every build image (feature `pdf`).
- Target names: `x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl`, `universal-apple-darwin`.
- A gate mismatch blocks that artifact (`BLOCKED_TARGETS` in `scripts/release.env`), never the others.
- Commit messages carry no AI reference. `sed` in this shell is `sd`; scripts call `/usr/bin/sed` or avoid it.

## Review Focus

1. A container build reports `"commit": null` in `--version --json` (no git in Alpine, or git's "dubious ownership" refusal across uids). Expected: the commit equals `git rev-parse --short HEAD`. Pinned in Task 2's self-check.
2. Two builds of one commit give different tarball sha256 (mtime, owner, gzip header, embedded `/Users/...` paths). Expected: equal Linux tarballs. Pinned in Task 6.
3. A pytest `tmp_path` under `/var/folders` or a cwd outside `/Users` is invisible inside the shim's container. Expected: the shim mounts both at the same paths. Pinned in Task 1's harness test.
4. `release.sh` on a dirty tree, or with a tag that does not point at HEAD. Expected: exit 2 before any build. Pinned in Task 2's harness tests.
5. A Linux binary on an old glibc host, or given a named `TZ` without tzdata. Expected: runs on CentOS 7; the named-zone result is recorded. Pinned in Task 6.
